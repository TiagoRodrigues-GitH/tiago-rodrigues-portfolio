# Deployment — site on GitHub Pages, API on Render, database on Neon

All three are free tiers. Nothing secret is stored in this repository: credentials live only in
Render's environment variables (production) and in a local file outside the repo (development).

## Frontend hosting vs. backend hosting

| | Frontend (`frontend/`, Angular) | Backend (`backend/`, Spring Boot) | Database |
|---|---|---|---|
| What it is | Static files (HTML, JS, CSS, images) built once | A Java process that must keep running, answer HTTP requests and talk to a database | PostgreSQL server holding the data |
| Where | **GitHub Pages** — serves files, cannot run code | **Render** (free web service, Docker) | **Neon** (free serverless PostgreSQL) |
| Address | `https://tiagorodrigues-gith.github.io/tiago-rodrigues-portfolio/` | `https://website-tiago-rodrigues-api.onrender.com` | private connection string, used only by the API |
| Deploys when | push to `main` touching `frontend/**` (`.github/workflows/deploy.yml`) | push to `main` touching `backend/**`, after the *Backend tests* workflow passes | — |
| Secrets | none (everything in it is public) | `DATABASE_*`, `JWT_SECRET`, `ADMIN_*` in Render | — |

The browser downloads the site from GitHub Pages and then calls the API on Render directly
(`environment.prod.ts → apiUrl`). Because they are different origins, the API only answers
browsers coming from `CORS_ALLOWED_ORIGINS`, and the site's Content-Security-Policy only lets it
connect to the API origin.

**Free-tier limits to know:** Render's free service sleeps after ~15 minutes without requests; the
next request waits about a minute while it starts (the site shows comments/statistics a bit later,
everything else is static and instant). Render's own free PostgreSQL expires after 30 days, which is
why the database is on Neon (no expiry, 0.5 GB). Neon also sleeps when idle and wakes in ~1 s.

## 1. Push the repository

Render and GitHub Pages build from GitHub, so `main` must be pushed first.

## 2. Database (Neon)

1. Sign in at <https://neon.tech> (GitHub login works).
2. **Create project** → name `portfolio`, PostgreSQL 17 or newer, region **AWS US East 1 (N. Virginia)**
   (same region as the Render service → low latency).
3. **Connect** → choose **Java** (JDBC). You get something like
   `jdbc:postgresql://ep-xxxx-pooler.us-east-1.aws.neon.tech/neondb?user=neondb_owner&password=...&sslmode=require&channelBinding=require`.
   Split it into three values:
   - `DATABASE_URL` = the URL **without** `user=` and `password=`, e.g.
     `jdbc:postgresql://ep-xxxx-pooler.us-east-1.aws.neon.tech/neondb?sslmode=require&channelBinding=require`
   - `DATABASE_USER` = `neondb_owner`
   - `DATABASE_PASSWORD` = the password

Tables are created automatically by the API on its first start (`spring.jpa.hibernate.ddl-auto=update`).

## 3. Admin password hash

The admin account is created at start-up from an e-mail and a **BCrypt hash** — the password itself
is never configured anywhere. On your PC, in the repository folder:

```powershell
cd backend
mvn -q test          # once, downloads the libraries the script uses
powershell -ExecutionPolicy Bypass -File scripts\bcrypt-hash.ps1
```

Type a strong password (≥ 12 characters, stored in your password manager), copy the printed
`$2a$12$...` line. Use a **different** password from the local development one.

## 4. API (Render)

1. Sign in at <https://render.com> with GitHub and allow access to this repository.
2. **New → Blueprint** → pick this repository → Render reads `render.yaml` and asks for the
   `sync: false` values:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL`, `DATABASE_USER`, `DATABASE_PASSWORD` | from step 2 |
   | `ADMIN_EMAIL` | the e-mail you will log in with |
   | `ADMIN_PASSWORD_HASH` | the hash from step 3 |

   `JWT_SECRET` is generated by Render; `CORS_ALLOWED_ORIGINS`, `REVIEW_PROJECTS` and
   `JAVA_TOOL_OPTIONS` come from `render.yaml`.
3. **Apply**. The first build takes ~5 minutes (Maven inside Docker). When the service shows
   *Live*, open `https://<service>.onrender.com/api/health` — it answers `OK`.
   If Render gave the service a different address than `website-tiago-rodrigues-api.onrender.com`,
   use that address below.

## 5. Connect the site to the API

From `frontend/`:

```powershell
node scripts/configure-services.mjs --api https://website-tiago-rodrigues-api.onrender.com
```

It sets `apiUrl` in `src/environments/environment.prod.ts` and adds the API origin to the
Content-Security-Policy (`src/index.html`, `public/_headers`). Commit and push; the *Deploy to GitHub
Pages* workflow publishes the site. (`--goatcounter <code>` optionally enables GoatCounter as well.)

## 6. Check

- Site → a project page → comments load (empty at first) and a test comment says *will appear after moderation*.
- Site → `/login` → admin e-mail + password → admin page shows the pending comment and visit statistics.
- Render → *Logs* shows no errors; Neon → *Tables* shows `reviews`, `visits`, `users`, …

## Local development

The `dev` profile (`application-dev.properties`) uses the local PostgreSQL in Docker. On this PC:
`Desktop\Backend-Dev\scripts\run-portfolio-backend.ps1` starts the API with the local credentials
(kept outside the repository), then `npm run start:proxy` in `frontend/` serves the site on
<http://localhost:4200> with `/api` forwarded to <http://localhost:8080>.

## If something fails

| Symptom | Cause / fix |
|---|---|
| Render build fails at `mvn` | open the build log; run `mvn -B test` locally in `backend/` to reproduce |
| Deploy never starts | `autoDeployTrigger: checksPass` waits for the *Backend tests* GitHub workflow — check the Actions tab |
| Service crashes: `Connection to ... refused` / `password authentication failed` | wrong `DATABASE_*` values; URL must start with `jdbc:postgresql://` and contain no user/password |
| Login always fails | `ADMIN_PASSWORD_HASH` must be the full 60-character `$2a$12$...` value |
| Browser console: *blocked by CORS* | `CORS_ALLOWED_ORIGINS` must be exactly `https://tiagorodrigues-gith.github.io` (origin only, no path) |
| Browser console: *violates Content Security Policy* | re-run `configure-services.mjs` with the exact Render address, commit, push |
| First request takes ~1 minute | normal on the free plan (service waking up) |
